Auth pattern (backend/auth.py):
    - Local dev (no X-Forwarded-Access-Token header):
          WorkspaceClient()  → profile auth from ~/.databrickscfg
    - Databricks App with OBO:
          WorkspaceClient(host=..., token=user_token, auth_type="pat")
      The `auth_type="pat"` kwarg is REQUIRED. Without it the SDK finds
      both the app's SP OAuth creds (DATABRICKS_CLIENT_ID/SECRET env) and
      the explicit token param, then refuses with:
          "validate: more than one authorization method configured:
           oauth and pat"

Per-surface auth map:
    | Call                                   | Auth    | Why                              |
    | -------------------------------------- | ------- | -------------------------------- |
    | gte-large-en embedding                 | SP (app)| Query vectorization, no user data|
    | Lakebase credential (generate_db_cred) | OBO     | User identity → Postgres         |
    | Lakebase Postgres connection           | OBO     | User authenticates as themselves |
    | SQL warehouse (survey enrichment)      | OBO     | UC row/column grants enforced    |
    | Genie One (onechat)                    | OBO     | Genie answers with user's grants |
