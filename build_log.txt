Implementation:

    [Backend]
    - backend/genie_one.py — in-process client for Genie One's workspace-wide
      data chat. Posts to POST /api/2.0/data-rooms/tools/onechat/responses
      (the same `onechat` service that backs `databricks genie ask` and the
      Genie One MCP). Request body uses the structured content shape
      [{"type":"input_text","text":"..."}] — a bare string is rejected with
      "Can not deserialize instance of scala.collection.Seq".
    - Auth is handled by WorkspaceClient().config.authenticate() which
      RETURNS the headers dict (does not mutate one). Same code path works
      locally (profile auth) and on Databricks Apps (service-principal /
      OBO auth) — no CLI subprocess needed.
    - Two entrypoints: ask() (blocking) and ask_stream() (SSE generator).
      The streaming version parses response.output_item.added events as
      they arrive and emits friendly progress hints (thought, inspect, sql,
      tool) to the frontend; final answer is synthesized from the terminal
      response.done event (output[] items with ui_type == FINAL_RESPONSE).
    - backend/main.py — exposed /api/genie-one/ask (JSON) and
      /api/genie-one/ask-stream (text/event-stream) with X-Accel-Buffering:
      no so events arrive incrementally.

    [Frontend]
    - frontend/src/components/ChatDrawer.tsx — global slide-out drawer
      mounted in App.tsx so both pages share one chat surface. Floating red
      FAB opens the drawer; conversationId is kept in component state so
      follow-ups continue the same Genie One conversation.
    - Streams SSE via fetch + ReadableStream (async generator parses the
      "data: {...}" lines). Progress events render as a pill-tagged
      timeline (thought / inspect / sql / tool) with a pulsing "Composing
      answer..." indicator; final answer replaces the thinking card.
    - Final answers go through react-markdown + remark-gfm so Genie's
      markdown (headings, lists, tables, links) renders properly. Executed
      SQL is shown in a collapsible <details> under the answer.
    - theme.css — chat drawer styles, markdown bubble styles, progress
      pills with color-coded kinds, dc-md-table-wrap scroll container so
      wide tables scroll horizontally INSIDE the pane instead of pushing
      the bubble off-screen. First column gets min-width 120px / max-width
      220px with a nowrap header so column titles like "Sailing Date"
      stay on one line.

Implementation:

    [New: backend/auth.py]
    - user_token_from(request) — reads X-Forwarded-Access-Token (Databricks
      Apps forwards the end user's access token in this header when user
      authorization is enabled).
    - workspace_for(user_token) — returns a user-scoped WorkspaceClient
      when a token is present, otherwise falls back to the default
      WorkspaceClient() (profile locally, SP on Apps). User-scoped clients
      are NOT cached — each request belongs to a different user.

    [backend/genie_one.py]
    - Added _auth(user_token) → (headers, host). OBO path builds
      Authorization: Bearer <user_token> directly; app-auth path uses
      cfg.authenticate(). Host comes from DATABRICKS_HOST env var under
      OBO.
    - ask() and ask_stream() both accept user_token. Genie One answers
      honor the END user's UC permissions when OBO is active.

    [backend/search.py — every surface threaded with user_token]
    - _lakebase_token(user_token) — OBO path mints a fresh Postgres OAuth
      credential per request via the user-scoped client (no caching —
      per-user token makes module cache unsafe). App-auth path keeps the
      55-min cache.
    - _lakebase_user(user_token) — OBO returns the END user's email / SP
      id, which Postgres authenticates as.
    - _lakebase_connection(user_token) — threads token into psycopg2.
    - _warehouse_connection(user_token) — under OBO, passes
      access_token=user_token directly to databricks-sql-connector; under
      app auth, uses the SDK's credentials provider.
    - embed_query, hybrid_search, enrich_survey_details, search,
      search_stream — all accept user_token and forward it so the serving
      endpoint, Lakebase, and warehouse all authenticate as the end user.

    [backend/main.py]
    - Each route now takes request: Request. For non-streaming routes we
      extract the OBO token inline; for SSE routes we extract it BEFORE
      building the generator (the Request object is only valid inside the
      route function, not inside the async generator body).
    - Local dev still works unchanged — no X-Forwarded-Access-Token header
      → user_token=None everywhere → falls back to profile auth.

    [app.yaml]
    - Declared user_api_scopes so Databricks Apps mints a user token with
      the right scopes:
        sql                        → SQL warehouse + Lakebase credential
        serving.serving-endpoints  → gte-large-en embedding endpoint
        dashboards.genie           → Genie One (onechat) chat
        iam.current-user:read      → current_user.me() for Postgres user

    [Frontend build + push]

      assets/index-*.css 13.99kB, assets/index-*.js 343.52kB gzip 107.96kB)
